# Demo Plan – "From raw conversations to prioritised action" with Looker

**Format:** 50 minutes of demo + 10 minutes Q&A. The demo is built around the 8 questions in the follow-up request.

**Story in one sentence:** we start from two raw files (PII-redacted transcripts and simple Genesys-style metrics), and no category
list was defined upfront. Looker shows what customers are talking about, what is new, what it costs, why it happens, what to fix
first, and the evidence behind every number.

---

## 1. What is planted in the mock data

About 6,200 conversations (calls and chats, ~18% in Swedish) from 1 July to 20 October 2026, generated by
`generator/generate_mock_data.py`. The numbers below come from the generator's ground truth for the last 28 days. The AI-classified
numbers you see in Looker will be close but not identical, which is a useful honesty point in itself.

| Storyline | What the audience should discover | Key numbers (last 28 days) |
|---|---|---|
| **Router firmware 4.2.1 on "Nova X3"** pushed 8 Oct | A brand-new issue that no category list would have had. Growing daily, 100% Nova X3, root cause = firmware update. For the first ~5 days agents did not recognise it and did factory resets, so repeat contacts are high | ~165 contacts in the last 7 days vs ~7/week before; AHT 17.5 min; CSAT 1.8; repeat 30% |
| **Price plan migration email** sent 22 Sep | Trigger-driven spike from long-tenure mobile customers. Longer AHT, lower CSAT, churn threats with competitor offers (the PDF's own example in 4.3.1) | 333 contacts; 82% tenure 5y+; AHT 13.2 vs 11.3 overall; CSAT 2.3 vs 3.1; churn 21% vs 9% |
| **Number porting web flow** | Journey gap: self-service fails without a reason, customer chats, then calls again within a week (PDF 5.3.1) | Repeat 37%; ~80% tried self-service first; chat → voice switching |
| **Broadband installation delays** | New customers (0–90 days), worst in the *OpenNet Syd* network (PDF 5.4.3) | Repeat 34%; CSAT 2.4 |
| **BankID app login incident** 11–24 Aug | Past incident concentrated in Skåne – region segmentation, before/after (PDF 5.9.1) | 168 contacts in two weeks, 71% Skåne |
| **Final invoice questions** | High-CSAT contact – "do not deflect" (PDF 5.18.1) | CSAT 4.2 |

## 3. Demo flow

### Act 0 – Framing (3 min)
- One slide: the architecture diagram from `docs/architecture.md`. Say: *"Everything you'll see runs on Google Cloud: BigQuery for
  data and AI, Gemini for understanding the conversations, Looker as the single governed place where the business consumes it."*
- BigQuery console, very briefly: one **Swedish** row in `raw_transcripts` next to the same `conversation_id` in
  `conversation_insights`. Point at `primary_issue`, `secondary_issues`, `trigger_event`, `root_cause`, `competitor_offer`,
  `evidence_quote` and `confidence`. Then show the SQL in `20_enrich_conversations.sql`: it's one SQL statement, with no category
  list in it.

### Act 1 – Transcript analysis without predefined categories (Q1) – 6 min
**Start page** (`VoC – Start Page`):
- *Top Topics* and *Weekly Contacts by Theme*: these topics were **discovered**. Gemini wrote a free-text label for every reason a
  customer raised, the labels were clustered by meaning, and Gemini named the clusters.
- **Explore → Customer Conversations**: `Topic (primary)` × `Issue Label (raw AI)` × `Contacts`. Many different phrasings,
  including labels from Swedish conversations, land in one topic. This is how themes emerge "without predefined categories".
- Add `Root Cause` and `Customer Sentiment` and pivot by `Theme`. Sentiment, root cause and trend all come from the same extraction.
- Mention multi-intent: `Number of Topics in Conversation` > 1 and the *Topics (incl. secondary)* view, where one call counts in
  every topic it raised, while `Contacts` stays de-duplicated.

### Act 2 – Discovery of emerging issues (Q5) – 7 min
- Start page → **Insight of the Day** (generated by Gemini from aggregated statistics) and the **Emerging Issues** tile: the
  router/Wi-Fi topic is flagged **NEW**, first seen ~8–9 Oct, ~160 contacts in 7 days vs a baseline near zero.
- Click the topic → **Topic Deep Dive**: daily ramp-up, spike days, hardware = Nova X3, root cause = firmware 4.2.1, repeat rate
  ~30%. In the evidence table, early conversations show agents doing factory resets and later ones naming the firmware. VoC
  would have spotted the pattern days before the front line did.
- **How it reaches stakeholders**: on the Emerging Issues tile click the bell → create an **alert** ("when any row exists, check
  daily, send to Slack/Teams/email"). Show **Schedule** on the dashboard (weekly PDF to the Fixed Broadband leadership group).
- Point out the price plan migration topic: it is not "new" any more, but it was a trigger-driven spike. The weekly trend shows
  when it started.

### Act 3 – Natural-language querying with follow-ups (Q2) – 8 min
Open **Conversations** with the *VoC Analyst* agent. Run these as one thread so the follow-ups keep context:

1. *"What were the main reasons customers contacted us in the last 4 weeks? Show contacts and unique customers."*
2. *"Which of these grew the most compared with the 4 weeks before?"*
3. *"Why is the Wi-Fi issue growing – what do customers say is the cause, and which routers are affected?"*
4. *"Visa samma sak för prisplansmigreringen: hur fördelar sig samtalen på kundens livslängd och hur påverkas AHT och CSAT?"*
   (Swedish question, Swedish answer, same numbers.)
5. *"How does churn compare for those customers versus other billing contacts?"*
6. Guardrail: *"What is the revenue impact of these issues?"* The agent should say revenue isn't available and offer the handling
   cost proxy (requirement 14.8.1).

For each answer, open the **query details**: which Explore, fields and filters were used. Say: *"It's not the LLM inventing a
number. It's the governed LookML model, so the dashboard and the chat give the same answer."*

**Questions that no field answers yet** – Explore **Ask the Transcripts** (analyst role):
- Question: *"The customer mentions working from home or online meetings"*, last 30 days, sample 300. Group by `Topic (primary)`:
  matches concentrate in the Wi-Fi topic, and the business impact (remote workers) is visible although nobody modelled it.
- Second question: *"The customer says they were not informed about a change in advance"*. This hits the migration, TV
  line-up and final invoice topics, which is a cross-topic communication issue.
- Point out sample size, match rate and estimated total: it's an estimate and labelled as one.

### Act 4 – Combining structured and unstructured data (Q4) – 7 min
Explore **Customer Conversations**:
- `Topic (primary)` with `Avg AHT`, `Avg CSAT`, `Repeat Contact Rate (7d)`, `Churn Rate (30d)`, `Unique Customers`. Every AI
  field sits next to every Genesys KPI at conversation grain.
- Filter Theme = *Billing & pricing*, pivot `Customer Lifetime`. Migration contacts come from 5–10 and 10+ year customers, with
  AHT +2 min, CSAT 2.3 vs 3.1 and churn 21% vs 9%. This is the requirement document's own example, reproduced from data.
- **Competitor mentions**: `Competitor Name`, `Competitor Offer`, `Competitor Price` for cancellations (e.g. Tre 100 GB for 299 kr).
- **Segments**: switch the date to August, `Topic` = app login, pivot `Region`. Skåne dominates during the incident window (customer
  segment + time + topic in one view).
- **Value chain view**: filter `Line of Business` = Fixed Broadband. Delivery, activation and Wi-Fi drive volume and repeat contacts
  (PDF 5.1.1 example), and the deep dive shows OpenNet Syd as the network context.

### Act 5 – Dynamic KPI creation (Q3) – 6 min
Three levels:
1. **Automatic**: the Wi-Fi topic did not exist before 8 October. When the pipeline discovered it, it got contacts, customers,
   AHT, CSAT, repeat rate, churn, cost, trend status and a priority score automatically, with no LookML change. Show the
   `topic_catalog` row and `taxonomy_change_log` (who/when/what – audit requirement 6.5.1).
2. **Self-service**: in the Explore, add a **custom measure** (e.g. "Contacts where customer tried self-service first") or use a
   table calculation with **Formula Assistant** ("share of repeat contacts that were transferred"). Save it to a new dashboard,
   share it with a team, and set an alert. This doesn't touch the governed baseline (9.2.1).
3. **Governed promotion**: open `conversation_facts.view.lkml` and show that `repeat_contact_rate` is defined once with a business
   description. An analyst promotes a successful custom KPI here via a Git pull request (LookML Assistant can draft it). An ad-hoc
   "Ask the Transcripts" statement that proves valuable becomes a new column in the extraction prompt (versioned, backfilled), and
   from then on it is a normal KPI.

### Act 6 – Prioritisation (Q6) – 5 min
- Start page → **Where to Focus**, or Explore **Issue Prioritisation**. The ranking combines volume, handling cost, experience,
  repeat contacts and churn. The *"Why this rank?"* column shows each component's percentile.
- Change the weights live (e.g. Churn 0.15 → 0.5). The migration topic moves up, which shows the logic is transparent and tunable.
- Open the topic: **Problem statement, Recommended action, Suggested owner, Expected impact**, generated by Gemini from aggregated
  numbers only.
- Failure vs value demand: `Demand Type` shows final-invoice and upgrade contacts as high-CSAT moments that should not be
  deflected (PDF 5.18.1), whereas PUK requests are already contained by the voicebot.

### Act 7 – Explainability (Q7) – 5 min
- From any number, **drill**: click `Contacts` → list of conversations with summary, evidence quote (Swedish and English) and
  confidence. Use the *AI Confidence* filter (High only) for a deep dive.
- Click a **Conversation ID** → transcript next to the AI summary, root cause and quote.
- **Governance moment**: *Sudo as* the "B2B CS Manager" user. They only see B2B contacts, the transcript field is not available,
  and the AI search Explore is hidden. Insights stay usable without identity data (6.1.1, 6.4.1).
- **Trust tiles**: Data Freshness (last load, late arrivals merged, duplicates removed), Transcript Coverage, and the
  `classification_status` values (No transcript / Excluded by privacy rule).
- **Quality**: `eval_runs` / `eval_topic_purity` in BigQuery. We measure the AI against a labelled set every time the prompt or
  model changes (14.5.2).

### Act 8 – End-to-end VoC workflow (Q8) – 3 min
Recap on the Wi-Fi example in one pass:
raw Swedish transcript → Gemini enrichment row → discovered topic → automatic KPIs → NEW flag + alert → priority rank → problem
statement + owner → (Looker Action creates a Jira ticket / scheduled weekly report) → the same dashboard tracks whether contacts
drop after the fix (before/after).

## 5. Likely questions and honest answers

- **"How accurate is the classification?"** It's measured, not assumed: golden set + `eval_runs`, with confidence per conversation
  and a filter on it. On the mock data you can show topic purity per discovered topic.
- **"Will the numbers change if I ask twice?"** No. Classification is stored once per conversation with model and prompt version,
  and every number is SQL over the semantic layer. Re-classification only happens as a versioned, logged run.
- **"What if something completely new happens tomorrow?"** The daily run labels new conversations in free text. Labels that don't
  fit existing topics become new topic candidates, and the trend logic flags them as New/Rising. That's exactly what happened with
  the router firmware.
- **"Does Looker analyse the text itself?"** No. Gemini in BigQuery does the language work. Looker is the governed layer that
  turns it into KPIs, conversations, alerts and actions, with security. This separation is what makes it reproducible and auditable.
- **"Swedish?"** The extraction reads Swedish and English transcripts; the agent answers in the language asked. The Looker UI and
  field labels can be localised to Swedish via LookML localisation files.
- **"GDPR / 60-day transcript deletion?"** PII is redacted before analysis, transcripts expire after 60 days, AI-derived fields are
  kept for 36 months, identity data is in no default role, and exclusion rules run before the model sees anything.
- **"What does it cost?"** It's driven by tokens per transcript × daily volume on a Flash-class model, run incrementally once per
  conversation. Size it with the customer's real daily volume (open question in the architecture document).
